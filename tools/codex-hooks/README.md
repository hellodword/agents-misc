# Codex hook helpers

These two optional Python helpers transport the patched Codex `RequestError`
and `AbnormalStop` events to a local desktop notification or an explicitly
configured webhook. They are operational examples, not an authenticated
network service.

## Data flow and authority

```text
Codex hook JSON on stdin
  -> codex_hook_forwarder.py validation, normalization, redaction, and bounds
  -> bounded HTTP JSON envelope
  -> codex_hook_notify_server.py validation and concurrency gate
  -> notify-send and/or configured webhook
```

The helper source in this directory is authoritative for the transport. The
hook payload and output schemas are generated by the pinned Codex tree and are
owned by `0006-generated-contracts.patch` in
[`codex/series.toml`](../../codex/series.toml). Do not copy those schemas into
this directory or add a second payload model.

The helpers produce no checked-in generated files. Runtime output is limited
to stderr diagnostics, desktop notifications, and configured webhook calls.
Raw payload forwarding is disabled unless
`CODEX_HOOK_FORWARDER_INCLUDE_RAW=1` is explicit.

## Security boundary

The receiver defaults to `127.0.0.1:8765`. It has no authentication or TLS, so
keep it on loopback. A non-loopback bind is only appropriate on an explicitly
trusted private bridge with independent firewall/access controls; never expose
it to a public or shared network.

The forwarder defaults to a conventional container-host gateway URL. For a
same-network-namespace setup, override it explicitly:

```sh
CODEX_HOOK_SERVER_URL=http://127.0.0.1:8765/hook nix develop .#codex --command python3 tools/codex-hooks/codex_hook_forwarder.py --help
```

Both sides cap request bodies at 2 MiB by default. The receiver admits eight
concurrent handlers by default and rejects configuration above 64. The
forwarder accepts only the stable model-request event fields, emits a compact
summary, and remains non-fatal unless strict mode is enabled.

## Run and configure

Inspect the two CLIs inside the pinned Codex shell:

```sh
nix develop .#codex --command python3 tools/codex-hooks/codex_hook_forwarder.py --help
nix develop .#codex --command python3 tools/codex-hooks/codex_hook_notify_server.py --help
```

Start a loopback receiver during local testing:

```sh
nix develop .#codex --command python3 tools/codex-hooks/codex_hook_notify_server.py --host 127.0.0.1 --port 8765
```

The receiver reads CLI flags and an optional TOML/JSON config. Its default
config path is `~/.codex/hook-notify-server.toml`; it does not read config from
environment variables. Empty or omitted `events` handles every validated
event.

```toml
events = ["RequestError", "AbnormalStop"]
max_body_bytes = 2097152
max_handler_concurrency = 8

[notify_send]
enabled = true
timeout_ms = 0

[webhook]
enabled = false
# Required when enabled: an absolute HTTP(S) URL.
# url = "https://your-reviewed-endpoint.invalid/notify?configured=value"
```

An enabled webhook receives a `POST` with `Content-Type: application/json` and
the fixed message shape
`{"msgtype":"text","text":{"content":"<title>\n<message>"}}`. If the
message is empty, `content` is only the title. Query parameters already present
in the configured URL are preserved; event fields are never added to the URL.
Redirects are rejected, and encoded webhook bodies are capped at 256 KiB.

Configure the forwarder with `CODEX_HOOK_FORWARDER_*` variables. The important
controls are event filtering, timeout, preview/body bounds, strict delivery,
verbose diagnostics, and raw-payload opt-in. Set `CODEX_HOOK_SERVER_URL` to an
absolute reviewed HTTP(S) endpoint. Review any command hook through Codex's
hook inspection UI before enabling it.

## Maintenance and validation

Run formatting, lint, unit/failure injection, schema generation, and the Nix
contract gate through pinned environments:

```sh
nix develop .#codex --command ruff format --check tools/codex-hooks
nix develop .#codex --command ruff check tools/codex-hooks
nix develop .#codex --command python3 -m unittest discover -s tools/codex-hooks/tests -p 'test_*.py'
nix build --no-link --accept-flake-config .#checks.x86_64-linux.codex-hooks
just codex-test
```

Tests cover old/unknown payload fields, raw opt-in, invalid URLs and limits,
body caps, content type/envelope rejection, bounded concurrency, timeout, and
delivery failure. CI uses only local synthetic requests and never invokes a
real webhook.

## Failure recovery

- Receiver refuses startup: run its `--help`, validate the config type/ranges,
  and return to the loopback default before widening any network boundary.
- Forwarder silently skips delivery: enable verbose mode, verify the event
  filter and absolute server URL, then inspect receiver stderr. Enable strict
  mode only when a hook failure should affect Codex hook status.
- Body rejected: reduce the preview/raw payload. Do not raise limits merely to
  forward opaque model data.
- Desktop notification unavailable: disable `notify_send` or run in an
  environment with the executable; the HTTP receiver can still acknowledge
  the event.
- Webhook failure: disable the webhook and validate locally. Never paste
  credentials into the tracked config or command example.

After a failure, the deterministic recovery proof is the helper unit suite plus
the `codex-hooks` Nix check. Neither command needs credentials or network
delivery.
