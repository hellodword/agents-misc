# Shared Rule Index

Use this index for every repository task, reusing it when already in context and unchanged. Select routes for the work actually being performed; multiple rows may apply. Revisit routing when new work is discovered, loading only newly relevant guidance. Loading and project references follow the [root loading policy](../../AGENTS.md#targeted-loading); this index selects shared rules and skills.

## Avoid incidental routes

- A database mention or query-only change does not require selecting a database or reconfiguring connections.
- Ordinary missing tools and minimal development-shell setup use the Nix rule without the Nix workflow skill. A Nix-installed executable alone does not make a task Nix workflow work.
- A working local NixOS VM test flow does not require remote execution. Ordinary Nix builds, executor provisioning, and systemd-nspawn tests do not trigger the NixOS VM test skill.
- Non-Nix browser tests use their project runner. Component tests and screenshots alone do not trigger browser E2E; screenshots alone do not trigger AI visual review.
- Dependency lockfiles use the dependencies route, even though tools generate them. Transient build output does not trigger the generated-artifacts route.
- Vue preferences apply only to an existing or explicitly selected Vue project.
- Task complexity, cleanup, ordinary implementation, and starting or resuming a Goal do not by themselves request a long-task plan.
- Tests passing, reviews, and status requests do not authorize commits.
