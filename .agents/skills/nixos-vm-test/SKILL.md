# NixOS VM Tests

1. **Scope and prerequisites:** Reuse working local VM flows when available. When local KVM is unavailable or remote execution is selected, check `service_get` and active `nix_job_list` (an offline worker pauses new admission because storage usage is unknown, while control and cleanup remain available). If neither `vm_test` MCP tools nor an authorized `--config` client file is present, use sufficient local project gates or report the missing host prerequisite directly; host setup follows the [VM Test MCP administrator guide](https://github.com/hellodword/agents-misc/blob/master/tools/vm-test-mcp/preparation.md).
2. **Test authoring:** Evaluate against the project's locked `nixpkgs` (`qemu.forceAccel = true`, explicit guest vCPU/RAM in node definitions, and deterministic synthetic credentials). Inside `nixosTest` `testScript`, launch long-running background processes via `systemd` units or `systemd-run` (or redirect stdin/stdout/stderr away from the command shell) so `succeed(...)` returns promptly instead of blocking on open inherited pipe descriptors. For initial executor acceptance, evaluate [assets/vm-smoke.nix](assets/vm-smoke.nix) with the project's locked `nixpkgs` to confirm multi-vCPU KVM guests, inter-node networking, and daemon sandbox isolation.
3. **Submission via `vm-test-submit`:** Always invoke `nix run github:hellodword/agents-misc#vm-test-submit -- ...` from an ignored workspace (`--work-dir`, e.g. under `tmp/agent/<id>/`):
   - **Direct client mode:** Pass `--config /abs/client.yaml` with `--test '.#checks.<system>.<name>'` (or `--smoke-project /abs/project` when running the bundled smoke module without `--test`) plus optional `--apply EXPR`, `--timeout-seconds`, and `--evidence manifest` to evaluate, upload the binary cache closure, submit, observe, and verify downloaded evidence. Reuse the same `--work-dir` to reconcile an interrupted call; create a fresh `--work-dir` and `--request-id` after editing test inputs.
   - **MCP tool mode:** Allocate `upload_create(kind="cache")`, run `nix run github:hellodword/agents-misc#vm-test-submit -- --test REF --request-id ID --upload-id ID --upload-url URL --work-dir DIR`, and pass stdout to `nix_job_create` (optional `wait_seconds` in `0..600`; pass `0` when batching alongside fast local checks, and pass `wait.continue` to `wait` when an observation window expires). Remove `<work-dir>/derivation` once the accepted `execution_id` is recorded.
4. **Diagnosis and truth separation:** Judge test assertions from the recovered driver receipt (`execution.test`) independently of the Nix client process exit. Read bounded `execution_log` windows (`limit <= 65536`) and `evidence_list` / `evidence_get` artifacts (stopping pagination when `items` is empty or `next_cursor` stops advancing). Diagnose guest behavior by editing the test and submitting a fresh execution while preserving signature checks and keeping the controller/worker account outside Nix `trusted-users`.
5. **Batch release and client settings:** One continuous batch occupies the FIFO slot until `resources.state` reaches `released` or `unallocated`; confirm release before starting another batch, and cancel abandoned queued/running jobs explicitly with `nix_job_cancel` (HTTP/tool cancellation ends observation only). When `manual_intervention: true` blocks release or evidence handoff, report `execution_id` and the structured cause (or run `execution_recover` after resolving the underlying issue) and continue independent local work. Pin evidence only when retention beyond default TTL is needed, and configure Streamable HTTP MCP clients with a single-call tool timeout of at least 660 seconds when using full 600-second observation windows.
