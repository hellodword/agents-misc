# NixOS VM Tests

1. Identify the project test, locked nixpkgs input, execution system and prepared MCP executor. Preserve a suitable project-local flow. Apply the [VM test conventions](../../rules/vm-tests.md) and read [execution](references/execution.md) for submission and diagnosis.
2. Prepare test changes locally; use `service_get` and the compact active `nix_job_list` to check the executor and queue. A configured offline worker pauses new admission because storage usage is unknown; existing control and cleanup remain available. This workflow does not provision the host. For a separately authorized setup task, read the [VM Test MCP administrator guide](https://github.com/hellodword/agents-misc/blob/master/tools/vm-test-mcp/preparation.md).
3. Use the independent `vm-test-submit` package inside the project environment: `--config` submits and downloads evidence automatically; for MCP submission, allocate a cache with `upload_create` and supply its upload ID/URL (optional `--apply EXPR` transforms `--test` before driver observation). If neither `vm_test` MCP tools nor an authorized `--config` path is present, follow local project gates when sufficient or report the missing host prerequisite without scanning private directories. It uses the project's locked framework, checks QEMU/KVM requirements, saves a fresh top-level derivation identity for retries, and uploads a standard binary cache. Retain local inputs while uploading or reconciling uncertain acceptance; release the local derivation GC root after recording the accepted `execution_id`, following the execution reference.
4. Submit the helper's JSON through `nix_job_create` (optional `wait_seconds` in `0..600`, where `0` enqueues and returns `wait.continue` immediately; avoid mixing long-blocking waits in the same parallel tool batch as fast local checks). Nodes run directly on host KVM inside the test build. Use `nix_job_get`, `nix_job_cancel`, `nix_job_extend` and `execution_recover` with `execution_id`. Read byte-offset logs (`limit` up to `65536`) and evidence (`evidence_list` stops when `items` is empty or `next_cursor` stops advancing) separately. Diagnose by changing the test and submitting a fresh execution identity. Preserve signature validation and keep the shared controller/worker account outside Nix `trusted-users`.
5. For initial acceptance, use [the multi-node test module](assets/vm-smoke.nix) with the project's locked nixpkgs. Confirm actual multi-vCPU guest startup and network assertions, alongside administrator-confirmed daemon sandbox policy.
6. Confirm `resources.state` is `released` or `unallocated` before the next executor batch. Track `evidence.state` separately (`wait(condition="complete")` can return `reason="attention"` without `manual_intervention: true` while `evidence.state` is `pending`/`collecting`/`transferring`—pass `continue` to `wait` until `complete`; only `manual_intervention: true` indicates a blocked state). Report an administrator blocker with its cause and continue independent local work. Cancel an abandoned queued task explicitly with `nix_job_cancel(execution_id=…)`; a disconnected observer does not cancel it. A new test batch rejoins the queue. Report the `execution_id`, execution system, driver assertion result, Nix client observation, logs, artifacts, resource release, collection and evidence state. Keep unresolved failures attributable to the test, execution environment or framework.

Configure your Streamable HTTP MCP client with a single-call tool timeout of at least 660 seconds (for example `tool_timeout_sec = 660` in Codex CLI 0.163.0+) or pass a smaller `wait_seconds` (`0..600`). Each default observation window is 600 seconds; transport heartbeats never require model polling. HTTP/tool cancellation stops observation only. Retention defaults to 1 day for success, 7 days otherwise and 30 days for summaries/receipts; pin needed evidence, then unpin when no longer needed. Protected evidence can pause new admission while control and cleanup remain available.
