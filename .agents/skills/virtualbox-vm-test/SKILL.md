# VirtualBox VM Tests

1. **Scope, templates, and node defaults:** Keep test scripts, assertions, and deterministic synthetic fixtures in the tested project. Check `service_get`, `template_list`, and active `lab_list` before acquiring the shared FIFO slot; missing host, router ISO, or template prerequisites belong to the [VM Test MCP administrator guide](https://github.com/hellodword/agents-misc/blob/master/tools/vm-test-mcp/preparation.md). Default nodes to headless (`gui: false`) with all media disabled, enabling `gui: true`, audio, `accelerate_3d`, or an allowed `nodes[].media.camera` alias only when the scenario requires them. VirtualBox guest ACPI S3/S4 sleep and hibernation are unsupported; use `node_control` hypervisor `pause`/`resume` instead.
2. **Staging, lab creation, and guest commands:** Upload immutable file inputs via `upload_create(kind="file")` (`PUT` `/manifest` then `/blob`) before calling `lab_create` with the batch's node list, ready `upload_ids`, deadline, and optional `wait_seconds` (`0..600`; pass `0` alongside fast parallel checks and continue expired windows with `wait`). Inspect `lab_inspect` for node IDs, deliver shared uploads via `guest_file_put`, and run workloads with `command_start` (`mode="finite"` waits for exit, process-group cleanup, and output retention; explicit `service` or `interactive` waits for start). Probe guest `PATH` and actual Python/Docker/Compose imports at runtime, installing missing project dependencies inside the disposable clone rather than mutating source snapshots.
3. **Networking and router leases:** Use internal LAN DNS `NAME.lab.test` (`10.77.0.0/24` default) for guest-to-guest traffic, especially when assertions depend on preserved client source IPs; use `endpoint_open` for inbound container-to-guest TCP/UDP access (whose host relay and loopback NAT path may rewrite source addresses). Toggle public egress or DNS via `network_set` as needed. Treat `network.state: "suspect"` as an active confirmed lease awaiting its next heartbeat, whereas `"degraded"` closes host relays and requires inspecting `execution_events` before calling `network_recover`.
4. **Windows desktop, UAC, and native input:** CLI commands run without interactive login (`context="service"`). When testing Windows GUI controls, image matching, UAC secure-desktop elevation, or firewall prompts, read [references/automation.md](references/automation.md) (with copyable harness assets at [run.py](assets/desktop-example/run.py), [scenario.py](assets/desktop-example/scenario.py), and [prepare-environments.ps1](scripts/prepare-environments.ps1)). Manage resolution policy through `node_display` and `lab_gui_set`. Whenever `node_input` returns an `uncertain` receipt, inspect a fresh `node_screenshot` before sending further input, and establish pass/fail from application state rather than input delivery alone.
5. **Bounded fault diagnosis:** Preserve running faults for bounded inspection rather than restarting or recreating nodes blindly. Correlate `node_get` (`health` across `virtualbox`, `guest_control`, and `commands`), `lab_diagnose`, `node_exec` (short absolute-path Guest Control escape hatch independent of the command supervisor), and timestamp-aligned `service_observe` metrics before attributing failures to host load or guest services.
6. **Batch conclusion, cleanup, and client settings:** Collect artifacts (`guest_file_get`, `evidence_list`/`evidence_get`, stopping pagination when `items` is empty or `next_cursor` stops advancing), submit the batch conclusion via `lab_finish` (or `lab_cancel` to abandon queued/preparing work; HTTP/tool timeouts stop observation only), and confirm `cleanup.state: "complete"` (`released` or `unallocated` resources) before starting another batch. If cleanup or evidence blocks (`manual_intervention: true`), inspect the recorded resource error before calling `execution_recover(scope="resources"|"evidence")`, or report the concrete blocker and continue independent local work. Pin evidence only when retention beyond default TTL is needed, and configure Streamable HTTP MCP clients with a single-call tool timeout of at least 660 seconds when using full 600-second observation windows.
