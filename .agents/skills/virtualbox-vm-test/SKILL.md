# VirtualBox VM Tests

1. Identify the prepared executor, required Windows/Linux templates, topology and evidence. Read [execution](references/execution.md) and apply the [VM test conventions](../../rules/vm-tests.md). Missing host, image or baseline prerequisites belong to the [VM Test MCP administrator guide](https://github.com/hellodword/agents-misc/blob/master/tools/vm-test-mcp/preparation.md).
2. Prepare the batch's scripts, dependencies and assertions locally. Allocate independent uploads, PUT immutable manifests and objects, and obtain ready inputs before acquiring the slot. Call `service_get` and the compact active `lab_list`, select each node's startup mode using the VM test conventions, then call `lab_create` with the complete node list, ready upload IDs and a batch deadline. Repeated templates create independent linked clones. Media requests must fit the advertised policy and default off. Creation waits for readiness; continue an expired window with `wait`, then read `lab_inspect` for node IDs.
3. Deliver bound inputs to nodes with `guest_file_put`, reusing one upload across the lab, then use `command_start` with guest argv. Probe Python/Docker/Compose through PATH and actual version/import commands; install missing task dependencies inside the clone, using offline uploads when useful. Linux nodes can run Docker/Compose. Use LAN names for guest-to-guest traffic and `endpoint_open` for allowed development-container TCP/UDP access. Public IPv4 egress can be toggled; a degraded router requires explicit `network_recover` after inspecting its task events.
4. Keep test code, assertions and dependencies in the tested project. For Windows control/image automation, read [standalone automation](references/automation.md) and select the product or executor-maintenance scope. Automatic login is optional: use screenshots and native input to inspect/login/unlock when needed. Use `node_display` and `lab_gui_set` for the exposed display policies, and capture evidence as needed. Inspect uncertain input receipts before sending another action; application success requires its own assertion.
5. Use `node_get` and `lab_diagnose` for preparation or runtime faults; `node_exec` provides short Guest Control commands independently of the supervisor. Preserve a running fault for bounded diagnosis; do not automatically restart or recreate nodes. Retain evidence before release and follow the shared batch lifecycle. Retry ended-task VirtualBox cleanup through `lab_cleanup` after inspecting resource errors.
6. Collect reports and capture artifacts, then submit the caller's conclusion and explanation through `lab_finish`. Use `lab_cancel` to abandon a queued or preparing task. Wait for complete cleanup before local rework, and use a new task for the next batch. Report task/node IDs, assertions, command exits, evidence and cleanup; retain unresolved evidence for diagnosis.

For a copyable starting point, use the example's [runner](assets/desktop-example/run.py), [scenario](assets/desktop-example/scenario.py), [input and matching helpers](assets/desktop-example/support.py), [vision subprocess](assets/desktop-example/vision.py), [Win32 fixture](assets/desktop-example/fixture.py), [template generator](assets/desktop-example/make_template.py) and [template](assets/desktop-example/target.png). Dependency inputs and generated locks are [controls.in](assets/desktop-example/controls.in), [controls.txt](assets/desktop-example/controls.txt), [vision.in](assets/desktop-example/vision.in) and [vision.txt](assets/desktop-example/vision.txt). The [environment preparation script](scripts/prepare-environments.ps1) is for an explicitly selected baseline setup or task-local environment directory.

Use Codex CLI 0.163.0+ with `tool_timeout_sec=660`. Each observation window is 600 seconds; transport heartbeats never require model polling. HTTP/tool cancellation stops observation only. Retention defaults to 1 day for success, 7 days otherwise and 30 days for summaries/receipts; pin needed evidence, then unpin when no longer needed. Protected evidence can pause new admission while control and cleanup remain available.

VirtualBox guest ACPI S3 sleep and S4 hibernation are unsupported. Hypervisor pause/resume remains supported. Finite commands wait for exit, group release and output; explicitly choose service/interactive mode for commands that must remain running. Lab duration defaults to one hour and cannot exceed 24 hours including extensions; waiting does not extend it.
